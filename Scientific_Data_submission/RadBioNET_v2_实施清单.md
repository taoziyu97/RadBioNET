# RadBioNET v2 可执行方法与记录清单

**文件状态：待实施方案，2026-11-13。** 配套英文 [Methods 草稿](RadBioNET_v2_Proposed_Methods.md)使用将来时，不能作为已经完成的方法提交。旧版 15,720 行是需要逐条迁移和核查的历史数据，不是正确答案。建议把新版本作为独立发布包，保留旧版和逐行映射。

## 先确定输出是什么

主关系表的一行应对应：**一篇文献 × 一个实验或临床比较 × 一个因素及其角色/操作 × 一个明确的照射臂 × 一个结果指标 × 一个方向**。同一文献的多个因素、照射臂、终点均可分多行。文献级的癌种、剂量或粒子词不能自动复制到所有关系行。一个记录至少要能追溯到 PMID、原文位置、两名审阅者的初判和最终裁决。

建议建立关系型原始表，再生成网站所需的扁平表。以下文件名是建议的交付清单，做完后用真实路径更新论文的 Data Records：

| 文件 | 每行的单位 | 必需的主要字段 |
|---|---|---|
| `search_runs.csv` | 一次检索的一个日期分段 | 流、查询版本、原始式、PubMed 译式、UTC 时间、日期范围、命中数、导出数、文件哈希 |
| `publications.csv` | 一篇去重后文献 | 稳定 publication_id、PMID、原 DOI、规范 DOI、题名、年份、期刊、发表/撤稿状态、来源流 |
| `screening_decisions.csv` | 一篇文献的一次审阅 | 阶段、审阅者、纳入/排除/不确定、单一主排除原因、裁决时间 |
| `experiments.csv` | 一个实验或比较 | publication_id、模型、癌种、对照臂、结果位置 |
| `irradiation_arms.csv` | 一个照射臂 | experiment_id、粒子大类、具体粒子、技术、靶材料、设备、剂量证据位置、归因层级 |
| `dose_mentions.csv` | 一处剂量表达 | 原字符串、位置、单位、剂量角色、范围上下界、单次剂量、分次数、总量、arm_id 或未分配 |
| `factors.csv` | 一个规范因素 | 原词、显示名、类型、标准库 ID、版本、歧义状态 |
| `evidence_relations.csv` | 一项因素—照射—结果关系 | 稳定 relation_id、publication_id、experiment_id、arm_id 或未解、factor_id、角色、操作、outcome、方向、证据位置、状态 |
| `annotation_decisions.csv` | 一个候选的一次审阅 | reviewer_id、独立初判、理由、证据、裁决、代码本版本和时间 |
| `legacy_crosswalk.csv` | 旧表到新版的一条映射 | 旧文件及行号、新 relation_id、拆分/合并/排除/待审、原因 |
| `validation_sample.csv` | 一条独立核验任务 | 抽样层、抽中概率、随机种子、字段判定、误差类型及修复版本 |

## 1. 先冻结代码本和检索方案

1. 确定纳入对象为 2000-01-01 至实际检索截止日的原始癌症放疗或放射生物学研究。细胞、动物和人群研究均可。文章需有可评估的**具体因素与照射反应**。没有原始结果的综述、只有计划/剂量学的论文、非电离辐射、撤稿论文等排除。临床因素与疗效或毒性相关的论文不要求强行提供分子机制。
2. 将[拟执行 PubMed 检索式](RadBioNET_v2_PubMed_searches.txt)作为初稿。先列至少 50 篇已知应纳入的“哨兵论文”，覆盖光子、质子、碳离子、混合照射、正常组织毒性、免疫及临床/基础研究。检查两个检索流的并集是否找回；找不到的逐篇分析，修改查询并留下版本差异。冻结后再开展正式检索。
3. 在代码本中给出每个字段的允许值、定义、正反例、缺失值语义和审阅顺序。先用 100 篇多样化文献双人独立试标，讨论分歧后冻结代码本。试标文献若进入正式数据，必须按冻结后的规则重新标注。

**记录而非预填：**实际截止日、正式检索式版本、哨兵论文清单及命中数、代码本版本、试标样本及规则变化。

## 2. 真正抓取并保存 PubMed 原始记录

1. 通用和质子查询分别运行。保存完整提交式、PubMed 的 Search Details 译式、UTC 时间、每个日期段命中数、PMID 列表、原始 XML、接口/工具版本。PubMed 的 ESearch 单次最多给出前 10,000 个 ID，因此对命中 ≥10,000 的日期段继续拆分，直至每段可完整取回。日期段不能重叠或留空隙。用 EFetch 分批下载 XML，遵守 NCBI 调用速率和 `tool`/`email` 规则。
2. 原始导出一经冻结便只读。保存每个文件的 SHA-256。通用、质子两流按 PMID 求并集，另存每个 PMID 属于哪些流；同一文章在两流出现不等于两篇文献。
3. 历史 NBIB/Zotero 输入作为独立的 legacy 流，保存原文件哈希；先用 PMID 连，再核查 DOI，最后人工判定题名、年份、期刊。旧行没被新检索命中时，给它单独的核查状态，不能悄悄删掉或直接判错。

**审计等式：**每个日期段 `返回 PMID 数 = 该段 PubMed 命中数`；流并集 `|A∪B| = |A|+|B|−|A∩B|`。数量不符就停止下游处理并排查。

## 3. 去重、撤稿核查和筛选

1. PMID 是 PubMed 文献的主键。保留 DOI 原文，规范 DOI 只用于匹配：去首尾空白、解析 `doi:`/`https://doi.org/` 前缀、大小写折叠、审查末尾标点。不要按分号拆 DOI。DOI 冲突或一篇多 DOI 要人工核查，不能只靠规范题名自动合并。
2. 两位审阅者独立看每篇文献的题名摘要。摘要不足、资格不明时进入全文筛选。每篇排除文献留下一个主原因，顺序固定为撤稿、同结果重复报道、无癌症/放疗语境、非电离辐射、无原创结果、无因素特异关系、材料不可得无法判断。后一个原因应计为“不确定”，不可伪装成确定不合格。
3. 第三人裁决不一致；保留两份原始判断。核查 PubMed 撤稿、纠错和关注声明，链接原文并判断是否改变记录。撤稿论文不输出为已接受关系。

**交付数字：**各流原始命中、重叠、去重后文献、初筛、全文筛、逐原因排除、纳入文献、纳入但无可接受关系文献。用这些数字绘制流程图。

## 4. 把自动匹配限定为“候选”

1. 冻结因素别名表和外部词表版本。人类基因优先 HGNC ID，药物/化学品可用 ChEBI ID，癌种用 NCIt，细胞系用 Cellosaurus。保留原词、规范名、标准 ID、别名来源、歧义和词表版本。通用缩写、跨物种基因、药物与靶点、路径与单基因要人工消歧。
2. 用可重复的规则识别标题、摘要和合法可读全文里的因素、照射、模型、癌种、剂量及方向词，保存原文位置、句子边界、命中的词典条目和程序版本。多因素 × 多方向同句仅产生多个候选，不自动成为多个真实关系。跨句只在指代明确时允许人工接受。
3. 标注是否为否定、假设、背景引用、Methods 描述或实际 Results。把候选与已接受关系分文件；如果来源无法确认关系或照射臂，状态记为 `uncertain`。

## 5. 两人独立核对每条拟发表关系

先确定“因素到底扮演什么角色”：直接干预的基因/蛋白、给药实体、药物靶点、观测性生物标志物、通路背景。再记操作：抑制/敲除、上调/激活、给药、耗竭、自然表达水平或未知。**药物作用不能直接写成靶蛋白本身的放敏效果。** 再看对照组、实际测量结果、结果方向和对应照射臂。仅当这些要素指向同一个比较，才可接受该关系。没有明确比较时，记录“相关性”或“不确定”，不要创造因果方向。

两人分别标注，不看对方结论；第三人裁决分歧。保存所有初判、裁决、理由和证据位置。可接受的证据位置是同句明确表达、前后句有可证实指代、或明确链接的图表与文字。题名或摘要里只提到某粒子/癌种，并不足以把它分配给全文每个实验臂。版权不允许发布原文摘录时，公开文件保留 PMID/DOI、章节或图表编号和简要原创证据说明，内部审阅表保留原句。

| 待判方向 | 必须看见的比较 | 不能据此判定的情形 |
|---|---|---|
| 肿瘤放射增敏 | 因素操作加照射相对于对应的单独照射，对肿瘤或癌细胞造成更强的预先定义的反应；同时记录指标的有利方向，例如克隆形成率下降或肿瘤控制提高 | 因素词与 radiosensitive 同句出现，但指标属于另一因素或另一实验臂 |
| 肿瘤放射抗性 | 同一比较中，因素操作与更弱的肿瘤照射反应相关；明确操作是敲除、过表达还是给药 | “敲低 X 使细胞增敏”被改写为“X 的表达使细胞增敏” |
| 观察性敏感性关联 | 仅有因素水平与放疗反应的相关性，保留关联方向和研究设计 | 无干预却声称该因素导致增敏或抗性 |
| 正常组织毒性增加或减少 | 明确的正常组织或器官终点、照射臂和比较对象，分别标记伤害增加与伤害减少 | 肿瘤细胞死亡或普通不良反应词被自动等同为正常组织放射毒性 |
| 免疫、DNA 损伤、表达变化或未检出差异 | 对应指标、方向、时间点和比较明示；未检出差异只描述所做检验 | 免疫激活直接等同于肿瘤增敏；统计不显著等同于证明无效 |

三个必须通过的原文例子：一篇论文同时有 X-ray 与 proton 臂时，3×8 Gy 只能分配给原文指明的那个臂；1.25 Gy mean heart dose 是危及器官受量；niraparib 的观察效果不能改成其靶点 PARP1 的直接干预效果。它们分别对应[多粒子剂量案例](https://www.frontiersin.org/journals/immunology/articles/10.3389/fimmu.2024.1286942/full)、[心脏受量案例](https://pubmed.ncbi.nlm.nih.gov/40353857/)和[药物靶点案例](https://doi.org/10.1002/hed.26155)。

## 6. 按实验臂而不是按文献分配粒子和剂量

1. 粒子大类和具体粒子分开。X-ray 与 gamma-ray 属于 Photon，质子属于 Proton；IMRT/SBRT/FLASH 是技术，不是粒子。`same_span` 或明确的 `arm_linked` 证据可以赋到关系行。`title_only`、`paper_only`、`ambiguous` 和 `not_reported` 作为上下文状态，不据此给多臂研究的每条关系填粒子。
2. 剂量先保留原字符串，再解析。`3×8 Gy` → 3 次、每次 8 Gy、总计 24 Gy；`60 Gy in 30 fractions` → 30 次、每次 2 Gy、总计 60 Gy；`250 cGy` → 2.5 Gy。`0–8 Gy` 保留上下界；`60 Gy(RBE)` 单独保留加权单位；`0 Gy` 是对照。不能默认 RBE = 1.1，也不能用范围中点取代原始范围。
3. 标记剂量角色：实验肿瘤/细胞照射、处方总量、单次剂量、危及器官受量、对照或不明。心脏平均剂量不等于肿瘤治疗剂量。只有来源明确把剂量连接到照射臂时才能填写 `arm_id`；文献里有多个照射臂而剂量归属不明时必须留空并标 `ambiguous`。解析器为每种语法建有标准答案的正反例测试。

## 7. 迁移旧版、复建和独立验证

1. 给旧 XLSX 每行按“冻结文件 ID + 行号”分配不可变 legacy ID。逐行标为一对一、拆分、合并、待审或排除，写入 `legacy_crosswalk.csv`。旧 `Strong/Weak` 只代表文本距离，旧 `Particle-specific verdict` 只代表聚合规则，均不能直接当作人工准确度。
2. 所有更正经过审阅记录，不在主 XLSX 直接覆盖。用原始文件和锁定软件环境从头重建，比较行数、主键、外键、各阶段计数、每个输出的 SHA-256。所有接受关系必须有文献、因素、结果、证据位置和裁决；臂级粒子/剂量必须有臂级依据；撤稿不能出现在接受表。把失败记录作为异常表保存。
3. 报告**裁决前**的双人一致率和各字段分母，再报告裁决结果。另从接受关系按来源流与粒子类别做有已知抽中概率的分层随机样本，建议 400 条，交独立审阅者盲法复核；另抽约 100 条高风险关系专用于发现错误，不能不加权并入总体准确率。逐字段给出正确数、有效分母和 95% 置信区间；同文多行需考虑按文献聚类。另抽已排除论文和已纳入论文重新通读以估计漏纳入或漏关系；没有有效抽样分母时不声称召回率。

## 投稿时把方法写成真实过去式

最终论文 Methods 只写实际做过的流程、软件与词表的准确版本、真实截止日、文件和参数。Data Records 列真实发布文件及列定义。Technical Validation 放复跑比较、人工一致率、抽样正确率、错误修复和剩余问题。不能把本方案中的 100 篇试标、400 条独立核验或双人全量审核写成已经完成。旧稿的 15,720 行、178 个显示标签等是**旧版观测数**，新版必须重新计算。

本清单的方法依据：[Scientific Data 投稿指南](https://www.nature.com/sdata/publish/submission-guidelines)、[PRISMA-S 检索报告清单](https://www.prisma-statement.org/prisma-search)、[NCBI E-utilities 文档](https://www.ncbi.nlm.nih.gov/books/NBK25499/)，以及 [EnzChemRED](https://www.nature.com/articles/s41597-024-03835-7)、[PubMed Knowledge Graph 2.0](https://www.nature.com/articles/s41597-025-05343-8) 和 [CT-EBM-SP](https://www.nature.com/articles/s41597-026-06608-6) 的 Data Descriptor 写法。PRISMA-S 用于完整报告检索过程，不代表本数据库已经构成系统综述。
